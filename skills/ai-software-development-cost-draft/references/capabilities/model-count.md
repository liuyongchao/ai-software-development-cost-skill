# 独立传统模型数量判定

## R — 原文

> 同时满足以下条件，可计为1个独立的传统人工智能模型：识别或预测目标对象不同；业务管控规则、判定逻辑不同；需要单独采集数据、单独标注、单独训练。

出处：6.3.3.2 a)5)，PDF第19页；多站点及共享排重见PDF第19–20页。

## I — 自述

模型数量取决于独立业务任务的证据，而非交付文件有多少。  
先说明每个候选在识别或预测什么，再比较候选之间的目标差异。  
业务管控规则和判定逻辑也必须不同，不能只靠换名称区分。  
还要证实需要分别采集、标注和训练，三组条件共同成立才能独立增计。  
同一任务装到多个工厂或设备上，仍只形成一个计数对象。  
部分共享、目标表述模糊时，保存待确认对象和证据缺口。  
计数完成后再关联模型工作包及数据活动，数量本身不直接等于工时或费用。

## A1 — 应用示例

原书未提供独立的模型计数案例。以下是明确标记的合成演练，按6.3.3.2 a)5)复核：A为缺陷识别任务，在5家工厂部署且共用训练；B为销量预测，题设已确认其目标、业务规则与判定逻辑、采集标注训练均与A不同；C仅新增一个销量预测模型文件，独立训练等情况未说明。

先把A的五个部署实例归为同一任务，再核实B的三组差异，得到已确认独立模型2个。C列待确认，补查其相对B的目标、规则和采集标注训练依据，不能把C写成永久不计或直接加1。演练没有真实项目实施结果。

## A2 — 未来触发

- 预算按工厂、摄像头或部署点计模型：“五个站点算几个模型？”／model count, deployment sites。
- 同一软件列出多个识别或预测任务：“这些模型能独立计价吗？”／independent models, recognition tasks。
- 新增模型文件或换算法后要求增计：“文件变了是否新增一个？”／model artifact, algorithm change。
- 多模型共享数据或训练流程，需审核重复数量：“共用数据还能分别算吗？”／shared dataset, duplicate counting。

与“独立智能体与内部节点判定”的区别：本卡查传统模型的目标、业务判定、采集标注训练；智能体卡查入口、内部能力及部署交付独立性。不能互借其中较宽的条件。

## E — 执行

输入契约：提供候选对象ID及名称、识别/预测目标、业务管控规则、判定逻辑、采集/标注/训练计划或记录、共享数据与算法框架关系、部署点、拟交付成果及来源位置。文字说明或附件引用均可；三组条件的状态分别为已证实、已否定、未知。计数单位为“个”，部署点数单列；缺证据须询问，不能填假值。

1. 建立候选表，区分业务任务、模型文件和部署实例；标明同一任务的比较对象。完成标准：每个候选均能追到目标和交付物，无法确定对象边界者已列待确认。
2. 逐对象比较三组条件，第三组分别检查采集、标注、训练，不以“重新训练”代替全部证据。三组全满足才列独立候选；任一未知或部分共享无法裁定时停止该对象增计。完成标准：每组都有状态、证据或待补问题。
3. 对同一识别任务多站点、共用数据集和算法框架而仅换点位的记录合并，保留被合并ID和理由。同软件的多个任务只有通过独立性检查才分别计量。完成标准：同一任务不会因文件、点位重复进入确认数量。
4. 输出“对象—三组证据—共享/部署关系—判定—计数归属—待补材料”台账，并列已确认数量与未决清单。关联各独立对象的数据活动，仅作为后续工作量评估接口；共享活动仍须按实际工作排重。完成标准：确认数可逐条复算，存在未决对象时明确总数尚未完全确定。

需要统一登记时先读配套 `calculator-guide.md`，再按其说明使用 `project-template.json`；`cost_calculator.py`不能替代业务独立性的证据判断。

## B — 边界

不按算法名、模型版本、权重文件、训练次数或部署数量自动计数。原稿没有覆盖所有部分共享情形，不能自行降低三组门槛，也不能将未知视为0。多站点不增加独立模型数，不代表实际部署工作必然免费；相关工作须另在任务边界中核实。本卡不提供模型性能评价、基准工时或单价。

## 相关能力

对比“独立智能体与内部节点判定”：先分清计数对象，再选择对应的独立性规则；混合项目分别留存两套判定证据。
